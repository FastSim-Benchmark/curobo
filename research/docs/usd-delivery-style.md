# 人工检查 USD 交付样式

本规范适用于本项目之后生成或重新打包、交给用户人工检查的 `.usd`、`.usda`
和 `.usdc` 文件。目标是让用户打开一个文件夹就能找到全部候选，打开一个入口
就能看到完整的场景、任务物体、机器人和工作区。原始资产及已封存运行保持只读，
新增检查入口写入派生交付目录。

## 1. 所有检查入口放在同一个文件夹

每次交付使用该 run 根目录下的 `human-review/`。同一轮的全部任务、场景和候选
的人工检查主入口直接放在这一层，不按任务或候选再分散到多级子目录。

```text
runs/<run-id>/human-review/
├── README.md
├── INDEX.json
├── <task-id>_<scene-id>_<candidate-id>_review.usda
├── <task-id>_<scene-id>_<another-candidate-id>_review.usda
└── deps/                         # 需要打包的依赖、辅助层、材质和资产
```

- 每个有效候选都要有自己的主入口；有三个候选就交付三个入口，不能只给第一个。
- 默认使用 `.usda` 主入口，体积较大的依赖可用 `.usdc`。文件名必须包含任务、
  场景和候选 ID，避免同一场景的不同方案互相覆盖。
- 辅助层和资源放在 `deps/` 或引用本机已验证、固定来源的文件；不要把辅助层
  当成主入口让用户逐个拼接。主入口引用优先使用相对路径。若交付需要搬到另一台
  机器，则把必要资源放进 `deps/` 并验证搬移后可解析。
- 不覆盖上一轮交付文件。无成功候选时，提供说明和空索引，不伪造可检查候选。
- 最终回复必须给出这个文件夹的绝对路径、全部候选入口链接和数量。候选很多时，
  给出完整的可点击文件索引，并说明索引中的总数，不能悄悄截断。

## 2. 每个主入口必须包含的内容

| 内容 | 展示要求 |
| --- | --- |
| 基础场景 | 加载本候选实际编辑后的场景，包括保留的家具、墙体、地板和门状态；体现本次移除、打开或替换，不能改用未编辑原场景。 |
| 任务物体 | 显示当前选中的真实资产几何，包括新增的搬运物、操作资产和替换资产；物体数量、身份、尺寸、朝向和支撑关系与该候选一致。不得只显示 workspace 来代替物体。 |
| 机器人 | 默认显示本 run 使用的完整机器人 USD 可视几何，使用实际机器人报告中的基准关节姿态和真实尺寸；初始位置、朝向与该候选的机器人初始工作区一致。站位框或碰撞球只能作为辅助。 |
| 操作工作区 | 显示任务物体的取放/操作 workspace，以及配对的 robot workspace；用半透明颜色和可识别名称区分角色、阶段和用途。 |
| 杂物 | 本入口对应含杂物实例时，显示该实例实际选择的杂物及其数量；无杂物候选明确标记为无杂物，不把未布置的杂物池当成场景中的物体。 |
| 标注与索引 | 保留 task、scene、candidate、instance、角色 ID、workspace ID 和对应 primpath，便于用户指出具体对象；检查辅助标注可切换显隐。 |

机器人真实资产不能加载、必要任务物体缺失或无法取得有效静态摆放见证时，记录
具体缺项并标为“人工检查交付未完成”。不得用普通方块或随意摆放的模型冒充
完整交付。预处理单独检查基础场景时，可交付标明 `scene_only` 的辅助入口，
但它不能代替任务候选主入口。

替换候选的正式源 USD 可能必须保留原占位体，供 LayoutGen 初始化计算目标 bbox。
人工检查入口应展示初始化后的替换结果：只在 `reviewOnly` 检查层隐藏已经通过
精确碰撞验证、且有真实替换资产的选中原占位体，避免旧家具与新资产重叠显示。
记录原路径和检查路径的映射；不修改正式源、原资产或生产碰撞门禁，不隐藏其他
家具、墙体或地板。`native_only` 原生交互对象必须保留。

## 3. 任务状态、工作区变体与可视辅助

- 主入口默认显示任务初始状态：物体在任务指定的初始支撑处，完整机器人在
  本候选起点；默认只显示一个候选、一个工作区变体和一个当前机器人实例。
- 已有多个工作区变体时，在入口中提供 `workspace_variant` 切换，默认 `000`。
  在 README 中说明选中哪个 prim、有哪些可用值；不要默认叠加所有变体。
- 连续任务提供有意义的 `task_state` 阶段切换，例如初始、第一件物体已放置、
  第二件物体已放置。动作顺序、左右手、持物状态和物体 ID 必须来自本次任务
  契约；同一物体跨阶段保持同一实例，不通过复制多个实体来模拟状态。
- 机器人在各操作阶段的基座位置、朝向绑定相应 robot workspace；未求出 IK
  时保留有依据的基准关节姿态，标为静态站位检查。不能补造手臂动作、抓取姿态
  或运动轨迹，也不能将静态见证表述为任务执行结果。
- 物体摆放优先复用本候选已有的有效静态见证。若候选只包含允许区域，需先
  生成并检查 review-only 静态见证，再显示具体物体；不能默认把所有物体
  堆在 workspace 中心。检查摆放不得改写正式 YAML 的允许区域或原始资产。
- 含杂物配置有多个采样实例时，可用 `instance_variant` 切换，或在同一
  `human-review/` 文件夹提供带 instance ID 的入口，并由索引完整列出。
  尚未得到杂物的有效具体布置时，明确标记为基础候选检查，不能宣称已完成
  含杂物实例的人工检查交付。
- 为便于观察，可提供相机、方向箭头、透明工作区及可选的站位/碰撞代理。
  多个站位的机器人示意默认隐藏，完整机器人默认可见。墙体遮挡时允许提供
  明确标记的 review-only 显隐辅助；默认仍保留完整场景，正式碰撞保持不变。

## 4. 缩放与坐标必须能直接检查

人工检查入口采用米制、Z-up、统一世界坐标，默认打开就能看到实际有效尺寸。

| 对象 | 有效尺寸规则 |
| --- | --- |
| 基础场景及原有家具、物体 | 源 USD 保持原生 `1.0`；检查入口应用一次 `1.2`。 |
| 新增搬运物体、杂物 | 额外 `scale = 1.0`；正确处理源单位换算，不继承环境的 `1.2`。 |
| 替换家具 | 允许按真实目标空间适配尺寸，展示本候选实际尺寸因子；正确处理单位、朝向、支撑和碰撞，不继承环境缩放。 |
| 机器人 | 保持真实尺寸，正确处理源单位，不继承环境的 `1.2`。 |
| workspace、摆放位置、机器人站位 | 坐标与有效放大后的场景一致；不能放大环境后仍使用原坐标，也不能重复放大已经换算的坐标。 |

例如毫米资产需要 `unit_scale = 0.001`；这属于单位换算，不是把新增物体放大。
环境、任务物体和机器人应使用明确分离的缩放继承关系，检查 resetXformStack
和实例引用等情况，不能只看父节点的 scale 字段。

README 和最后回复写明：**入口已经应用场景 1.2，查看器额外 scale 保持 1.0。**
检查入口标记 `reviewOnly`，不能把已经缩放的检查场景作为正式源场景再应用
YAML 的 `base.root_scale = 1.2`。正式配置仍遵守源场景 `1.0`、YAML 放大一次。

## 5. README 与 INDEX

`README.md` 至少包含：任务原文或准确说明、候选数及其对应场景、每个入口的
用途、默认状态、阶段/工作区/实例切换方法、颜色含义、主要对象和机器人
primpath、缩放规则，以及本轮尚未验证的项目和已接受的源资产缺陷。

`INDEX.json` 为每个主入口记录 task ID、scene ID、candidate ID、可选 instance
ID、文件名、来源 run/交付配置、可用 variant、默认值、机器人与物体的来源、
角色/工作区 primpath、缩放核查结果和人工审核状态。基础候选、含杂物实例、
场景单独检查应明确区分。默认人工审核状态为 `pending`，收到实际人工反馈
后才更新。

## 6. 交给用户前的检查

1. 对照本次成功候选清单核对入口和索引数量，确认没有漏交候选。
2. 用 `isaac5` 的 USD 工具实际打开每个主入口和其可用 variant，检查引用、
   defaultPrim、单位和 upAxis；必要资源可解析。已确认且接受的源贴图缺失
   单独记录，不把新产生的引用断裂混入原资产缺陷。
3. 核对实际 composed 几何：环境有效缩放一次 `1.2`，新增资产和机器人保持
   原生实际尺寸；workspace 和摆放坐标正确。不能只检查 YAML 字段。
4. 核对每个状态中的物体身份、数量、真实支撑、朝向、阶段占用，以及机器人
   的位置和可视完整性；检查层不得移除生产碰撞来制造通过结果。
5. 在现有 USD 查看器或已有渲染工具中检查默认画面，确认机器人、任务物体和
   工作区可见、辅助显示不遮蔽主要内容。若只完成 USD 数据回读，记录“可视
   打开待人工确认”，不冒充已完成画面复核。
6. 保存检查结果、入口和必要来源的 hash；规范文档与 AGENTS.md 作为之后
   使用本规范的运行输入一并记录。保持正式产物和原资产不变。

最终报告按实际边界说明“候选生成成功”“配置编译成功”或“可进入 LayoutGen”。
人工审核、真实抓取、IK、LayoutGen 求解和仿真执行分别记录，不用可打开的
检查 USD 代替它们的验收。
